# Wrist Vehicle Bridge Frontend

Private Next.js dashboard for authenticated, wrist-friendly Tesla vehicle controls. The app keeps all backend credentials server-side, exposes a dark mobile-first UI, supports PWA installation, and integrates browser Web Push subscriptions without handling VAPID private keys in the frontend.

## Quick start

```bash
npm install
cp .env.example .env.local
npm run dev
```

Open [http://localhost:3000](http://localhost:3000), sign in with Google, and use the protected dashboard.

## What this app does

| Area | Capability |
| --- | --- |
| Auth | Google SSO with optional email allowlist. |
| Vehicle status | Reads live vehicle status through a server-only backend client. |
| Vehicle commands | Sends live commands with server-side validation and sensitive-command confirmation. |
| PWA | Provides manifest, custom icons, and conservative service worker caching for installability. |
| Push notifications | Lets the browser subscribe/unsubscribe to Web Push through authenticated Server Actions. |

## Architecture

```text
src/app/                    App Router entrypoints and protected dashboard
src/auth.ts                 Auth.js configuration
src/features/auth/          Sign-in/sign-out UI and actions
src/features/vehicle/       Vehicle UI, schemas, server actions, backend client
src/features/push/          Push UI, schemas, server actions, backend client
src/components/             App shell, providers, UI primitives, SW registration
public/sw.js                Service worker: static cache + push display handlers
public/icons/               PWA icons
skills/                     AI project knowledge generated by bootstrap
```

The browser never talks to private backend endpoints with the client API token. Client components call Server Actions; Server Actions authenticate the user and delegate to server-only clients.

## Environment

Create `.env.local` from `.env.example` and configure:

| Variable | Purpose | Browser-safe? |
| --- | --- | --- |
| `TESLA_BACKEND_URL` | Backend base URL for vehicle/push endpoints. | No |
| `TESLA_CLIENT_API_TOKEN` | Private bearer token used by server-only backend clients. | **Never** |
| `AUTH_SECRET` | Auth.js secret. | No |
| `AUTH_TRUST_HOST` | Auth.js host trust setting for deployment/proxy environments. | No |
| `AUTH_GOOGLE_ID` | Google OAuth client id. | No |
| `AUTH_GOOGLE_SECRET` | Google OAuth client secret. | No |
| `AUTH_ALLOWED_EMAILS` | Optional comma-separated sign-in allowlist. | No |
| `NEXTAUTH_URL` | Local/deployed Auth.js URL. | No |

## Security rules

- Never expose `TESLA_CLIENT_API_TOKEN` to client code, props, service workers, logs, or browser storage.
- Keep `Authorization: Bearer ...` only in server-only backend clients protected by `import "server-only"`.
- Use `cache: "no-store"` for authenticated backend fetches.
- Server Actions that read or mutate private backend data must require an authenticated session first.
- Validate backend payloads with Zod before trusting them in UI.
- The service worker must not cache `/api/`, auth, vehicle, push, dashboard, or navigation responses.
- Sensitive commands (`unlock`, `openFrunk`, `openTrunk`) require explicit UI confirmation before execution.

## PWA and Push

### Installability

The app includes a native App Router manifest, custom non-branded icons, and a conservative service worker. Test installation from a secure context:

1. Open the deployed app on a mobile browser.
2. Sign in.
3. Use “Install app” / “Add to Home Screen”.
4. Relaunch from the home screen and verify standalone display.

### Push subscriptions

Push is frontend subscription management only:

1. The browser requests notification permission.
2. A Server Action fetches the VAPID public key from the backend.
3. The browser creates a `PushSubscription`.
4. A Server Action registers/deletes the subscription using the authenticated session email.

The frontend does not send push messages and never handles the VAPID private key.
